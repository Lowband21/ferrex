# Scan orchestration boundary contracts

This note pins the current black-box seams before scan orchestration is extracted. Tests should prefer public ports (`QueueService`, `ScanRunRepository`, `LibraryCommandExecutor`, `SeriesScanStateRepository`, `ScanCursorRepository`) and existing adapters instead of private implementation details.

| Boundary | Production owner | Contract to preserve | Owner tests |
| --- | --- | --- | --- |
| Folder scan unit planning and cursor completion | `dispatcher.rs`, `scan_cursor.rs`, `FolderScanActor` | A `FolderScan` lease plans through the folder actor, compares the durable cursor, emits `FolderScanCompleted` for every completed unit, and short-circuits unchanged listings without discovering media or enqueueing follow-up jobs. | `dispatcher::tests::unchanged_cursor_folder_scan_emits_completion_without_followups`; `dispatcher::tests::folder_scan_dispatch_enqueues_follow_up_work` |
| Public scan-run starts and progress | `scan_run.rs` | `get_or_create_active` is idempotent per `(library, mode)`, returns `Reused` for active runs, keeps separate modes independent, and reserves terminal transitions for `mark_terminal`. | `scan_run::tests::get_or_create_active_reuses_same_library_mode_run`; `scan_run::tests::concurrent_get_or_create_active_reuses_one_run_per_library_mode`; `scan_run::tests::progress_update_rejects_terminal_status`; `scan_run::tests::mark_terminal_rejects_non_terminal_status` |
| Filesystem watcher handoff | `fs_watch/mod.rs` | Watch messages are debounced per library root, persisted before actor handoff when a durable bus is present, acknowledged only after successful handoff, and burst events in one debounce window are dispatched as one `FsEvents` command. | `fs_watch::tests::fs_watch_service_coalesces_burst_into_single_command`; `fs_watch::tests::fs_watch_service_persists_before_dispatch_and_acks_after_handoff`; `fs_watch::tests::fs_watch_service_skips_duplicate_idempotency_keys` |
| Maintenance planning | `maintenance.rs` | Interval maintenance is due for enabled auto-scan libraries regardless of live watcher state, discovers new root children, plans stale cursors oldest-first, and honors per-pass limits. | `maintenance::tests::due_maintenance_does_not_require_live_watchers`; `maintenance::tests::plan_discovers_new_top_level_folders_without_watch_events`; `maintenance::tests::plan_prioritizes_new_root_folder_before_stale_cursor_when_limited`; `maintenance::tests::plan_enqueues_only_stale_existing_cursors` |
| Queue merge and correlation | `persistence.rs`, `enqueuer.rs`, `correlation.rs`, `runtime/supervisor.rs` | Active ready/deferred/leased dedupe rows merge instead of duplicating work; enqueue producers publish accepted/merged job events through the enqueue facade; terminal rows can be re-enqueued; correlation ids remain stable across enqueue, merge, dequeue, and completion; merge events do not inflate scheduler ready counts. | `persistence::tests::enqueue_reuses_ready_deferred_and_leased_dedupe_rows`; `enqueuer::tests::enqueue_publishes_accepted_event_and_caches_correlation`; `enqueuer::tests::merged_enqueue_uses_existing_correlation_and_reports_priority`; `dispatcher::tests::correlation_ids_are_stable_across_merge_dequeue_and_completion`; `supervisor::tests::scheduler_observer_skips_ready_for_merged_events` |
| Series gating and no-demotion | `series_state.rs`, `dispatcher.rs` | Episode matching stays deferred until the matching series root resolves, resolution releases only that dependency, and a resolved series state is not demoted by later discovery/seed events. | `dispatcher::tests::episode_match_dependency_key_defers_until_release`; `dispatcher::tests::series_resolve_releases_episode_match_and_reaches_index`; `series_state::tests::mark_seeded_does_not_demote_resolved_state`; `series_state::tests::mark_discovered_does_not_demote_resolved_state` |
| Runtime scheduler accounting | `scheduler.rs`, `runtime/supervisor.rs` | Ready counts move into reservations, confirmed reservations become in-flight work, cancellation restores readiness, and completion releases in-flight capacity without allowing merge events to create phantom work. | `scheduler::tests::reservation_accounting_tracks_ready_cancel_inflight_and_completion`; `supervisor::tests::scheduler_observer_skips_ready_for_merged_events` |
