The operator guide is the home for running Ferrex safely. It prioritizes user data, recovery, and observable service behavior over implementation internals.

## Operator topics

| Topic | Content that belongs here | Current source material |
| --- | --- | --- |
| Installation | Docker or Podman startup, host prerequisites, service layout, and first-run checks. | `README.md`, `docker-compose.yml`, `docs/unraid.md` |
| Configuration | Environment variables, media paths, logging, reverse proxy assumptions, and safe defaults. | `docs/configuration.md`, `.env.example` |
| Security | Network exposure, authentication, device sessions, and operational threat model. | `docs/auth-security.md`, `.github/SECURITY.md` |
| Library operations | Scan lifecycle, metadata expectations, artwork behavior, and retry guidance. | Server and scanner docs as they are promoted. |
| Client recovery | Phone, TV, and desktop state reset/retry guidance before feature expansion. | Mobile and player QA notes as they are promoted. |
| Demo mode | Local demo data, reset behavior, and what is safe to show publicly. | `docs/demo-mode.md` |

## Recovery-first writing

Any page that asks an operator to change state should include a recovery path. For example:

- restarting a failed service without deleting media or metadata;
- refreshing stale client cache without requiring an app-data wipe unless that is the documented last resort;
- regenerating code or metadata with the exact command and expected output;
- preserving logs that help diagnose server, scanner, auth, or playback failures.

## First pages to promote

The strongest candidates for full Starlight operator guides are configuration, Unraid deployment notes, auth/security, and demo mode. They already answer real user questions and can be converted without waiting for deployment automation.
