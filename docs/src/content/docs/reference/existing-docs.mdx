Ferrex already has useful markdown notes under `docs/`. This inventory keeps them discoverable while the Starlight site grows around reader-focused sections.

## Operator-facing notes

| File | Use when promoting content |
| --- | --- |
| `docs/configuration.md` | Convert into setup and configuration pages with environment-variable context and safe defaults. |
| `docs/unraid.md` | Promote into an operator deployment guide with storage paths, ownership, and update notes. |
| `docs/auth-security.md` | Split into operator security guidance and developer authentication invariants. |
| `docs/demo-mode.md` | Convert into a demo setup and reset guide. |
| `docs/faq.md` | Use as a source for short troubleshooting entries and landing-page links. |

## Bench artifacts

`docs/bench_results/` contains benchmark result JSON files. They should remain data artifacts unless a performance reference page needs to summarize a stable benchmark methodology.

## Promotion rule

When a note becomes a full Starlight page, keep the original path referenced until inbound links are updated or a redirect/deployment strategy exists. This avoids breaking existing README and issue links during the docs-site scaffold phase.
